# 游戏开发规则

Owner：本文件。Rule ID：GAME-TRACE-01 / GAME-CONFIG-01 / PLATFORM-FACT-01。

## 需求、实现与调试

先核验当前游戏目标、版本、阶段、相关架构约束与已有实现。说明触发动作和期望结果，选择能完成需求的最小完整切片，不引入无关抽象。新功能应包含必要状态、配置、UI 反馈、失败/取消路径及与现有模块的接入；纯文案机械修改不要求这些不存在的阶段。

涉及资格、解锁、奖励、存档、路由或状态转换时，追踪产品规则→谓词 owner→运行入口→真实 caller→场景/配置绑定，检查正例、反例和边界值。“仓库有正确 helper”不能证明运行时会调用它。幂等奖励、重复点击、重入/取消、场景切换和重启只在相关时核查。

## 配置与资源事实

涉及序列化、资产、场景、平台后台或部署时，检查需求↔代码默认值↔持久化/序列化配置↔运行绑定↔外部后台↔运行证据。每层定位真实 owner，不适用标 N/A；冲突时先确定运行时读取哪层，不能仅改代码默认值后声称修复。

Unity 项目按影响读取实际 scene/prefab/ScriptableObject、GUID/.meta、Inspector 引用和资源加载路径；源码检查不能代替场景绑定。避免无关资产重序列化，不编辑 Library/Temp 等生成结果来修复源问题。其他引擎沿自己的真实资源和场景路径核验，不强制套用 Unity 目录。

UI 修复从实际可见对象、交互动作和运行 owner 定位，遵循项目已有设计约束；样式或文案正确不能证明点击、遮挡、返回和状态反馈正常。音频、经济、存档等参数以其项目 owner 与运行配置为准，不植入通用业务默认值。

## 外部平台条件门

只有任务涉及平台 SDK、广告、分享、排行榜、支付、权限、云能力或发布时触发：编码前核验当前官方一手文档、日期、实际 SDK/vendor 版本、项目 wrapper/adapter、后台/权限前置和最低验证环境。不得凭记忆猜 API 或绕过已有 adapter 把 vendor 调用散落进业务。

微信小游戏条件检查：分享不默认等于可可靠验证的回流或奖励；激励广告仅按 verified completed 回调发奖，覆盖关闭、错误与重复回调；排行榜分开世界榜、好友榜、身份/授权、云端数据和开放数据域；广告位、AppID、隐私授权、域名/CDN 和云函数版本以实际后台事实为准。不把某个项目的奖励额度、解锁条件或后台值写成公共规则。

缺关键平台事实时继续授权内的调研、接口、mock 或明确 fail-closed 路径，不能声称生产可用。导出成功不能证明部署成功；发布/回滚版本需同时定位代码、资源、配置与云服务。公开推荐或易变化的平台事实使用当前官方来源，案例仅用于取舍辅助。

测试和结论按 verification.md；读写边界按 boundaries.md；长期记录按 memory.md。
