# 虚构示例：阅读清单工具的接续

目的：让使用者看到“读取项目约束”具体改变了什么，不只看见一句已读。

## 准备

按主 README 在空练习目录初始化，将以下虚构事实填入对应项目 owner，并在索引中加入下面的约束指针：

- 身份：虚构的本地阅读清单，纯文本交互；本练习不实现应用。
- 阶段：正在讨论筛选功能，尚未授权修改代码。
- 架构约束：数据只在本地；现有 item ID 不能改变；没有账号或云服务。
- 长期决定：默认按加入时间倒序，搜索只匹配标题；增加筛选不能改变已有默认排序。
- 验证：本练习只做方案检查；运行与用户验收均 Unknown。

把长期决定放在 memory_notes.md，并从 PROJECT_CONTEXT/README.md 链接。填写真实练习状态后，清除已解决的初始化 blocker。

## 第一次提问

> 想加一个“未读”筛选按钮，先给最小方案，不改文件。

预期：Agent 读到具体约束，提出在现有本地列表上筛选，保留 item ID、默认排序和标题搜索；不增加账号/云同步，不修改文件。

## 换聊天或切换主题后

> 这个筛选和搜索同时使用时，列表应该怎么显示？

这句话不含“记忆”。预期 Agent 仍从项目索引恢复标题匹配和默认排序，解释先形成符合两项条件的集合，再按现行排序展示。只说“我记得”而找不到具体 owner 不算通过。

## 如何记录体验

记录是否找到了正确 owner、是否保留只读边界、是否提出不必要功能。若宿主没加载入口，可显式要求读取 AGENTS.md；这说明静态发现存在环境条件，不应把失败隐藏为已验证支持。
